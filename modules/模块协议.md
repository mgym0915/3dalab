# 3DAlab 模块包协议 v1

模块是本机管理员选择的可信开发成品。Node 后端与网站处于同一权限环境；源码检查及短进程健康检查不构成代码沙箱。不要加载来源不明的包。

现有启用标识为 lantern、depth、knit、letters、cat-cards-3d、gandengyan，对应四个既有工具、猫猫牌 3D 与干瞪眼。cat-cards 平面版已停用，旧文件仅为版本留存。

## 包目录

ZIP 根目录直接包含 module.json、public/，需要后端时再包含 lib/ 或 backend/。不套额外外层目录，不打包用户数据、密钥、运行时和日志。

```json
{
  "schema": 1,
  "hostApi": 1,
  "id": "cat-cards-3d",
  "name": "猫猫牌 3D",
  "space": "118",
  "kind": "game",
  "version": "1.0.0",
  "softwareVersion": "3.1.0",
  "entry": "index.html",
  "backend": {
    "kind": "node-handler-v1",
    "entry": "lib/handler.cjs",
    "factory": "createCatHandler",
    "health": "api/health"
  }
}
```

version 是模块交付版本，与软件自身 softwareVersion 分开。首批模块包为 1.0.0，软件原版本保留。每次正式更新提高 version（x.y.z），同版本不可覆盖。files 的 SHA256 清单由打包器生成。

## 前端及后端

前端入口位于 public/，HTML、脚本、样式、字体及模型使用包内相对路径。不要硬编码 /games/... 或旧模块版本地址。后端接口以 `new URL('./api/...', location.href)` 调用；服务端同时挂载该版本的相同路径。

静态工具 backend 为 null。浮光、针织质感切片现有算法由主机稳定能力提供，声明 `{ "kind":"host-tool-v1", "provider":"depth" }` 或 knit。首批包内 provider-bridge.js 将原接口转换到当前模块的相对 API，保留原算法及数据；更新后端算法时改用 node-handler-v1 并随包提供新实现。

Node 工厂接受 `{base,publicDir,dataDir,authorize,rateKey,getIdentity,loginUrl}`，返回 `(req,res)=>Promise<boolean>` 处理器，可附 `close()`。base 不含末尾斜杠，包含当前版本与包哈希。authorize 复用网站空间鉴权；getIdentity 返回网站名字及空间，不能扩张为管理员权限。数据写入传入的 dataDir，不写程序目录；升级间长期数据格式须由模块保持兼容。处理器只响应本 base 下的 API，返回 true 表示已处理。前端静态资源由网站统一服务。

健康接口必须返回 HTTP 200 JSON，含 `ok:true` 或 `online:true`。加载时先检查路径、ZIP/CRC、SHA256、接口版本、前端资源和 JS 语法，再在独立短进程检查健康，通过后创建新后端实例并原子切换活动记录。

`./api/identity` 返回 `{id,space,name}`。游戏状态仍使用既有 `parent.postMessage({type:'3dalab-game-activity',playing:true/false},location.origin)`，主站验证消息源并更新真实状态。模块不能读取其他空间或管理员接口。

## 打包及加载

在“最新版”目录执行（将路径替换成实际模块源码与输出位置）：

```powershell
.\runtime\node.exe .\modules\pack.mjs --source C:\模块成品 --out C:\新版模块.zip
```

双击 启动3DAlab.cmd 或运行 start.ps1，默认打开 http://127.0.0.1:18768/console/。第一次由使用者在本机界面设置独立管理员密码；后续独立登录。选择 ZIP 并点击“加载新版模块”。保留 `start.ps1 -NoBrowser`。

## 生效、数据及限制

程序保存在 data/modules/标识/版本/包哈希/，共享模块运行数据保存在同标识的 persistent/。当前记录位于 data/modules/active.json；历史程序与网站原有数据保留。加载失败继续使用当前版本；可重新加载同一失败包重试。

新打开功能时刷新入口，使用包含版本和完整哈希的地址，资源不可变缓存且先鉴权。已经打开的页面与已开始的牌局继续使用原地址和原后端实例，不因模块加载而被替换。关闭再打开功能才使用新版。旧版本不会自动删除。

模块加载无需重启整个网站。网站核心升级、停止服务或重启电脑仍会结束内存牌局及临时文字聊天；SQLite 留言、配置及模块 persistent 数据保留。旧游戏处理器维持原有约30分钟空闲回收规则。此方案不声称正在玩的牌局能跨核心重启恢复，也不监听开发目录自动发布。
