# 自定义角色导入规格 v1.0

适用于本次更新后的 3DAlab 角色控制器。交付 `.glb`，一个文件一个角色；`.blend` 是制作源文件，不是网站导入格式。以后开放用户上传时，以这份约定作为接入标准。**本次未增加上传入口、账号存储或自动骨骼重定向。**

## 1. 哪些模型能用

| 级别 | 必须具备 | 能做什么 |
| --- | --- | --- |
| 基础展示 | glTF 2.0 GLB、可见网格、完整内嵌资源 | 显示、整体平移和转向；不代表有表情或步态 |
| 完整交互 | 绑定好的骨架、有效的头部权重、`mouthOpen` 形变、`Idle` / `Walk` / `Jump` 动画 | 稳定待机、走路、起跳、点头、摇头、连续张嘴 |
| 可移交动作包 | 在完整交互基础上增加 `Nod` / `ShakeHead` / `Talk` | 其他支持 glTF 动画的引擎也能直接播放三个表情动作 |

本次九个新版角色均按“可移交动作包”制作。没有腿的饼干、胡萝卜、鱿鱼允许用摆动、蹦跳或触须步态，**不要求硬加人类四肢**。静态模型不会被自动生成真实步态或嘴部开合。

## 2. 格式、材质与尺寸

- 格式：glTF 2.0 `.glb`，缓冲、图片等资源全部内嵌。交付中不使用需要额外解码器的 Draco、Meshopt 或 KTX2 扩展；这些格式只有在网站另行配置解码器后才能纳入支持范围。
- 坐标：GLB 为 Y 向上、角色面向 +Z；单位米。Blender 建模时 Z 向上、角色面向 -Y，使用 Blender glTF 导出的默认 Y Up 转换。
- 地面原点：角色站立最低点在地面 Y=0；根控制器在地面原点。模型整体位置为零、缩放为 1；导出前应用制作缩放，避免负缩放。
- 材质：glTF 标准金属粗糙度 PBR；可使用基础颜色贴图或顶点颜色。Blender 的噪声、驱动器、自定义着色节点不能直接作为网站材质，需要烘焙或转换。新版加载器保留导入材质和贴图。
- 建议预算：单角色 1 万三角面以内、1～4 个材质、64 根骨骼以内、贴图以 1024 为主、文件 10 MB 以内。这些是移动端制作建议，不是现有加载器已经实施的拒绝阈值，也不保证所有机型帧率。
- 不导出摄影地板、灯光和相机。角色尺寸最终归一到约 0.83 米展示高度；如提供 `height` 描述字段，必须是 GLB 静止姿态的实际高度。

## 3. 骨架与蒙皮

推荐骨架：

```text
root                         地面锚点；不在动作中移动
└─ motion                    原地步态的上下起伏
   ├─ torso                  躯干／呼吸控制
   │  ├─ head                有实际蒙皮权重的头部／面部本体
   │  ├─ arm.L → hand.L      有手臂时使用
   │  ├─ arm.R → hand.R
   │  └─ 耳、尾、衣摆等可选骨骼
   ├─ leg.L → foot.L         有腿时使用
   └─ leg.R → foot.R
```

`root`、`motion`、`torso`、`head` 是本套示例的约定名；第三方骨骼可通过 `characterSpec.bones` 映射根、动作、躯干和头骨。`leg.L/R`、`arm.L/R` 是无 Walk 动画时的有限兼容回退名；非同名的四肢依赖模型自己提供的 Walk 动画。

头部控制不能是一个空骨骼：头部、眼睛、嘴、角等需要一起跟随。饼干这类头身一体的角色，把整个饼干及表面装饰绑定到 `head`；胡萝卜同理，叶片可通过子骨骼跟随。普通动物只把头和面部附件绑定到头骨。

每个顶点权重归一化，最多 4 个骨骼影响；关节附近保留足够环线，权重渐变。删除无效顶点、零面积面和重复面，修正法线。嘴、眼、牙等可保留为独立网格岛，但必须有正确的蒙皮。单网格不是硬性要求。

当前程序的点头／摇头在头骨的局部 X／Y 轴叠加旋转：**局部 X 为左右方向的点头轴，局部 Y 为向上的摇头轴**。仅重命名骨骼不能修正不兼容的骨骼轴向。第三方模型需在 DCC 中调整轴向或烘焙到约定骨架；当前没有通用人体自动重定向。

## 4. 张嘴必须是实际形变

推荐在面部网格添加形态键／Morph Target：`mouthOpen`。

| 数值 | 含义 |
| --- | --- |
| 0 | 自然静止表情；已有微张嘴角色可保留小开口 |
| 0.5 | 中等开口 |
| 1 | 完整张嘴，嘴腔和下唇／下嘴壳形变正确 |

形变名称会作为 GLB 的目标名称导出；可用 `characterSpec.morphs.mouthOpen` 映射其他名字。形变只影响嘴、下唇／嘴壳和必要的邻近皮肤，不能把整个脸拉长。嘴腔必须有深色内壁，避免看到头部背面。鸭子应同时移动下嘴壳。静止表情不得出现悬空黑球。

当前实时张嘴走 Morph Target 通道，不直接识别任意 `jaw` 骨骼或材质切图。只有下颌骨的模型应在制作软件中烘焙出 `mouthOpen` 后再交付。缺少该通道时，规格上属于不支持张嘴，不能以完成表情任务的模型验收。

## 5. 动画片段

名称区分大小写，推荐直接使用以下名称；如不同，可配置 `characterSpec.clips`。

| 名称 | 推荐时长 | 循环 | 制作要求 |
| --- | --- | --- | --- |
| Idle | 2～4 秒 | 是 | 微呼吸、轻微附属物摆动；脚底稳定 |
| Walk | 0.8～1.2 秒 | 是 | 步态明显，左右交替；无腿角色使用本体摇摆／蹦跳 |
| Jump | 1 秒 | 否 | 起跳预备、空中姿态、落地缓冲；首尾返回中立 |
| Nod | 约 1.2 秒 | 否 | 绕头骨局部 X 点头，起止中立 |
| ShakeHead | 约 1.2 秒 | 否 | 绕头骨局部 Y 摇头，起止中立 |
| Talk | 约 1.2 秒 | 否 | 动画中实际包含嘴部 `weights` 通道，不能只有头骨旋转 |

**位置驱动约定：**全部动作禁止平面根位移。网站控制前进、转向和离地高度，动作只提供相对姿态与原地步态的小幅起伏。`Jump` 不再烘焙整个人的跳跃高度，否则网站物理高度和模型高度会叠加。Jump 按归一化时间划分为 0～22% 预备、22～78% 空中姿态、78～100% 落地缓冲。

新版网站按移动状态切换 Idle／Walk／Jump，只播放对应身体动作并短暂混合；点头、摇头为交互输入叠加到头骨，张嘴为连续控制 `mouthOpen`。不会把全部动画同时播放。Nod／ShakeHead／Talk 保留在模型中供其他引擎直接播放。

## 6. 可选的语义映射

在角色骨架根对象的自定义属性 `characterSpec` 中保存 JSON 字符串，导出 GLB 时启用 Custom Properties。网站也接受解码后位于节点 `extras.characterSpec` 的对象。同目录 `characterSpec.example.json` 给出完整示例。

```json
{
  "version": "1.0",
  "bodyType": "body",
  "bones": {"root":"root","motion":"motion","torso":"torso","head":"head"},
  "morphs": {"mouthOpen":"mouthOpen"},
  "clips": {"Idle":"Idle","Walk":"Walk","Jump":"Jump","Nod":"Nod","ShakeHead":"ShakeHead","Talk":"Talk"},
  "jumpVerticalMotion": "runtime",
  "forward": "+Z",
  "up": "+Y"
}
```

`bodyType` 为 `biped`、`tentacle` 或 `body`，用于记录制作类型；本版步态以实际动画片段为准。缺少映射时按上面的约定名称查找。

## 7. 交付前验收与后续上传入口

制作方先在 Blender 导出，再重新导入实际 GLB；检查颜色、蒙皮、动作和 Morph Target。重点验收：摇头／点头时面部附件一起跟随；`mouthOpen=1` 有正确开口；Walk 循环接缝一致；Jump 起止为中立且不自带世界跳高；停止后能回到 Idle。

后续上传入口应先解析文件并展示“展示／头部／张嘴／Walk／Jump”能力结果，缺什么就明确标记，不能宣称静态模型具备完整交互。上传文件大小、外部 URI、资源数量和异常数值等服务端校验，需要在真正开发上传功能时实施；本规格不表示这些上传保护或用户存储已经上线。

底层文件格式依据：[Khronos glTF 2.0 官方规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)。骨骼和动作名称、角色预算及混合方式是本项目约定，不是 glTF 强制标准。
